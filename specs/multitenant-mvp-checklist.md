# 멀티테넌트 MVP 구현 체크리스트

이 문서는 [MVP 명세](multitenant-mvp.md)의 구현 순서와 완료 증거를 관리한다. 정책의 원문은 MVP 명세에만 두고, 구체적인 기능 명세와 API 계약은 해당 작업 전에 `specs/`에 추가한다. health, 인증, 조직 선택과 핵심 문서 흐름이 구현되어 있으며 데모 운영 기능은 아직 구현되지 않았다.

상태 열은 서로 독립적이다. **확정**은 해당 행에서 명시한 정책이 결정되었다는 뜻이지 모든 세부 정책이 결정되었다는 뜻은 아니다. **필요**는 아직 작성·구현·실행해야 함을 뜻하고, **해당 없음**은 API 계약이 필요하지 않다는 뜻이다.

| 단계 | 항목                                 | 정책                                            | API 계약  | 구현 | 검증 |
| ---- | ------------------------------------ | ----------------------------------------------- | --------- | ---- | ---- |
| 1    | migration·seed·격리 MySQL·기본 CI    | 확정: 순방향 migration 및 기존 데이터 보호      | 해당 없음 | 부분 | 부분 |
| 2    | 가입·세션·CSRF·요청 제한·로그인 화면 | 확정: 세션·CSRF·제한·인증 감사 실패 정책        | 완료      | 완료 | 완료 |
| 3    | 조직 선택·테넌트 경계                | 확정: 활성 멤버십·교차 조직 404                 | 완료      | 완료 | 완료 |
| 3    | 문서 생성·수정 및 최초/변경 이력     | 확정: 원자성·revision 우선·no-op                | 완료      | 완료 | 완료 |
| 4    | 카테고리·삭제·휴지통·과거 버전 복원  | 확정: 버전과 revision 전이·복구 이력 종류       | 완료      | 완료 | 완료 |
| 5    | 멤버 변경·감사 및 최소 화면          | 확정: 대상과 지정 역할·감사 원자성              | 완료      | 완료 | 완료 |
| 5    | 제목·본문 검색·권한별 화면           | 확정: 한국어 부분 일치·초성/오타 제외           | 완료      | 완료 | 완료 |
| 6    | 데모 제한·초기화·감사 정리·운영      | 확정: 일반 데이터 보호·경합·실패·감사 보존 정책 | 필요      | 필요 | 필요 |

## 단계별 요구사항 → 계약 → 검증 → 완료 증거

각 계약에는 경로·메서드, 인증/권한, 입력·출력, 오류 코드 및 예시를 기록한다. 현재 존재하지 않는 API나 명령은 예시로 지어내지 않는다.

### 1. 기반

- **요구사항:** 빈 DB에서 순방향 migration과 안전한 seed, 격리된 테스트 MySQL, 기본 CI를 준비한다. 기존 Docker health를 유지한다.
- **계약:** migration·seed 실행과 재실행 및 실패 절차를 문서화한다. 업무 API는 해당 없음.
- **검증:** 빈 DB 재현과 seed 재실행, 복합 FK의 교차 테넌트 관계 거부, 테스트 DB 격리 및 롤백을 확인한다.
- **완료 증거:** 실제 실행 가능한 root 명령과 결과, 실패한 경우 CI 실패 기록. 기존 `pnpm verify`를 시작점으로 사용하고 실제 MySQL 테스트가 추가되면 CI에도 연결한다.

### 2. 인증 흐름

- **요구사항:** 가입, 세션, CSRF, 요청 제한, 신뢰 프록시, 로그인 및 조직 없음 화면을 제공한다.
- **계약:** [인증 API 계약](auth-api.md)에 가입·로그인·현재 사용자·로그아웃의 입력·응답과 same-origin 프록시, 쿠키·CSRF 및 인증 감사 실패 동작을 정리했다.
- **검증:** 중복 가입, 잘못된 로그인, 만료·폐기·사용자 정지, 로그인 전 CSRF 만료와 로그인 시 회전, 반복 토큰 조회·캐시 방지, Origin 누락·불일치 및 요청 제한을 확인한다. 성공 로그인 감사 실패 시 세션 미발급, 로그아웃 감사 실패 시 세션 폐기와 로그 파일 기록, 실패 로그인 감사 장애 시 계정 비노출과 로그 파일 기록을 확인한다. 브라우저에서 실제 API를 통한 로그인·쿠키 전달·만료·로그아웃을 확인한다. JSON 본문의 압축 해제 후 바이트 크기가 한도 이하일 때 파서가 수용하고, 초과 시 잘림 없이 `413`인지 확인한다.
- **완료 증거:** 격리된 실제 MySQL에서 `pnpm test:integration:mysql`, 실제 API·DB를 사용하는 브라우저에서 `pnpm test:e2e:auth` 통과. fixture 기반 health E2E는 인증 검증으로 간주하지 않는다. 공용 배포를 위한 만료 데이터 정리와 데모 reset은 단계 6에 남아 있다.

### 3. 핵심 문서 흐름

- **요구사항:** 조직 선택, 활성 멤버십과 권한, 문서 생성·조회·수정 및 이력 저장을 함께 구현한다. 생성과 최초 스냅샷, 수정과 변경 스냅샷은 각각 같은 트랜잭션이다.
- **계약:** [조직·문서 API 계약](documents-api.md)에 경로·입출력·오류 우선순위와 PATCH의 `categoryId` 생략·null 및 `expectedRevision` 문자열 의미를 정의했다.
- **검증:** A 조직 문서에 대한 B 접근과 권한 부족이 겹쳐도 `404`; 같은 조직 내 역할 부족은 `403`; 같은 revision에서 서로 다른 변경을 동시에 제출하면 한 요청만 성공; 오래된 revision과 동일 내용은 `409`; 정상 no-op은 버전·revision·`updated_at` 유지; `categoryId` 생략은 유지하고 null은 연결 해제; 이력 저장 실패 시 문서 변경 롤백. 최초 이력도 확인한다.
- **완료 증거:** 격리 MySQL에서 `pnpm test:integration:mysql`, 브라우저→프록시→실제 API→DB에서 `pnpm test:e2e:documents`를 실행한다. 로컬 통과 및 CI 설정은 완료됐으며 원격 CI 실행 결과는 별도 확인이 필요하다.

### 4. 카테고리·복구

- **요구사항:** 카테고리 관리, 문서 삭제·휴지통 복구, 과거 버전 복원과 기존 이력을 확장한다.
- **계약:** [카테고리·복구 API 계약](recovery-api.md)에 경로·권한·카테고리 선택과 이력 응답을 정의했다. 카테고리가 변경된 휴지통 복구 이력은 `trash_restore`다. 삭제 문서 일반 상세·이력은 `404`; 별도 휴지통 이력 조회는 MVP 범위 밖이다.
- **검증:** 카테고리 삭제와 연결의 경합, 삭제 문서 일반 경로 404, 카테고리 변경 유무별 휴지통 복구 버전·revision 및 `trash_restore` 이력, 동일 내용의 과거 버전 복원도 새 이력 생성, 이력 실패 롤백 및 교차 테넌트 복구 거부를 확인한다.
- **완료 증거:** 격리 MySQL에서 `pnpm exec vitest run --config vitest.mysql.config.ts tests/integration/mysql/documents.test.ts` 7개 통과, `pnpm test:e2e:documents` 1개 통과. 원격 CI 결과는 확인하지 않았다.

### 5. 멤버·검색·화면

- **요구사항:** 멤버 변경 API와 감사, 한국어 검색, 최소 멤버 화면, 역할별 UI, 허용 요소를 제한한 기본 Markdown 미리보기와 입력을 보존하는 충돌 안내를 제공한다. 조직 감사 조회는 owner/admin용 최소 API, 인증 감사는 운영자 절차로 제한한다.
- **계약:** [멤버·감사 API 계약](members-api.md), [검색·미리보기 계약](search-preview.md)과 [인증 감사 접근 절차](../docs/operations/audit-access.md)를 작성했다.
- **검증:** 기존 역할과 지정 역할을 함께 검사해 비활성 admin 재활성화를 owner만 허용하고 admin의 admin 지정은 거부한다. 성공 감사 저장 실패 시 멤버 변경 롤백, 거부 기록 분리와 실패 보고, 다음 요청에 권한 변경 반영을 확인한다. `휴가`로 제목과 본문의 `연차 및 휴가 신청`을 각각 찾고 삭제 및 타 조직 결과를 제외한다. 검색의 대소문자·`%`·`_` 리터럴, 정렬 동률, 페이지 크기와 잘못된 offset/limit의 `400`을 확인한다. 충돌 시 미저장 입력과 Markdown·링크 안전성을 확인한다.
- **완료 증거:** 멤버·감사·검색은 격리 MySQL의 `pnpm exec vitest run --config vitest.mysql.config.ts tests/integration/mysql/documents.test.ts` 11개 통과, 미리보기는 `pnpm test:unit` 및 실제 API 브라우저 `pnpm test:e2e:documents` 통과. 원격 CI 결과는 확인하지 않았다.

### 6. 공용 배포

- **요구사항:** 공용 데모 제한, 안전한 초기화, 감사 보존 정리, 백업·복구 및 운영 문서를 마련한다. 별도 초기 설정·데모 데이터 전송용 bootstrap API는 범위 밖이다.
- **계약:** reset 대상 조직 쓰기와 데모 세션 발급의 차단·진행 중 작업 종료·초기화 순서, 실패 후 차단 유지와 안전한 재실행, 생성 시 지정한 전용 데모 계정 및 보존 감사 로그 보호를 운영 절차로 구체화한다. 기존 seed와 신뢰된 수동·예약 reset은 유지한다.
- **검증:** 서로 다른 조직을 포함한 초기화 간 직렬화와 사용자 요청과의 경합, 차단 중 데모 로그인 성공 자격 증명의 `503`과 실패 응답의 계정 비노출, 중간 실패·프로세스 종료 후 차단과 재실행을 확인한다. 계정 유형 불명·혼합 멤버십 시 변경 없는 중단, 여러 데모 조직에 속한 대상 계정의 세션 폐기, 일반 데이터·사용자·세션 및 보존 감사 로그 보호, 30일 정리·백업 복구를 격리된 환경에서 확인한다.
- **완료 증거:** 실제 API E2E, CI 결과, Docker health 및 검증된 운영 명령. 공용 배포는 이 조건 충족 전에는 하지 않는다.

## 검증 명령 현황

- 현재 root 명령: `pnpm verify`, `pnpm test:unit`, `pnpm test:integration`, `pnpm test:e2e`. `pnpm verify`는 브라우저 E2E를 포함하지 않는다.
- 실제 MySQL 테스트는 초기 migration·seed, 복합 FK와 부분 DDL 실패, 인증 및 핵심 문서 API의 격리·경합·롤백을 검증한다. 이후 단계의 기능은 포함하지 않는다.
- 단계 1~6의 실제 DB·API 시나리오는 해당 통합 테스트를 추가한 뒤 `pnpm test:integration:mysql`으로 검증한다. 기본 CI는 `pnpm verify`와 격리 MySQL 테스트를 각각 실행한다.
- 단계 2 인증은 `pnpm test:e2e:auth`, 단계 3·4 문서와 복구 흐름은 `pnpm test:e2e:documents`로 실제 API·DB를 검증한다. 단계 5~6은 추가 브라우저 테스트가 필요하다. `pnpm test:e2e`는 health fixture만 사용하므로 MVP 흐름의 완료 증거가 아니다.
- 실제 MySQL과 브라우저 실행·격리 방법 및 필요한 새 root 명령은 구현 시 관련 README에 추가하고, 각 체크리스트에 실행 결과를 기록한다.
